Problem definition

Working professionals on ChatGPT mobile in India rarely use voice for work prompts. They know the mic exists and many have tried it once. They return to typing because voice feels less safe: words can become the prompt before they read and fix them.

  • Who: Employed mobile users in India, 3+ sessions/week, email/summary/analysis prompts.
  • Business value: Higher voice completion → longer sessions, stronger Plus retention.
  • User benefit: Speak when busy; same control as typing before the model runs.
  • Why now: WhatsApp and Gemini teach review/interrupt; Milestone 2 showed control, not discoverability, is the gap.

User flow

  1. Mic visible in composer.
  2. Tap mic → speak → stop.
  3. Transcript in dashed draft (not sent).
  4. Tap word to edit; optional low-confidence underline.
  5. User taps Send → message enters thread → model responds.
  6. Discard returns to keyboard without sending.

Wireframes

Annotated screens in Figma Make prototype (link above): default composer, recording, draft state, inline edit, after Send. Phase 2 “Structure this” shown but disabled.

Key logic

  • Never auto-send speech to the thread.
  • Empty recognition → stay in draft with hint.
  • First-run one line: “Voice stays as a draft until you send.”
